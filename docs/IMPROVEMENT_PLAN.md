## 1. Data layer
- [x] 1.1 Chuẩn hoá contract tìm kiếm: `YouTubeDataRepository.searchVideosWithStatus` trả `Success(videos)` khi hoàn tất (kể cả rỗng), không map rỗng thành `Failure(Network)`. `YouTubeWebDataSource.search`/nguồn con phân biệt parse thành công (trả danh sách, có thể rỗng) với thất bại nguồn (mạng/cấu hình/parse/response lỗi) và ném lỗi khi mọi nguồn thất bại, để tầng repository/UI phân biệt "không có kết quả" với lỗi.
- [x] 1.2 Hợp nhất parse thời lượng: thêm `parseDurationSecondsOrNull` dùng chung và cho `InnerTubeJson.durationSeconds` delegate vào parser chuẩn trong `data.model.VideoItem`.
- [x] 1.3 Hợp nhất schema/mapping settings: tạo `SettingsCodec` dùng chung cho serialize/parse `AppSettings` (JSON backup) và parse/encode sponsor modes/whitelist; `BackupManager` và `SettingsStore` dùng chung codec để giảm lệch schema/default/mapping.
- [x] 1.4 Hợp nhất mapping `VideoItem`/`VideoEntity`/JSON: thêm `videoThumbnailUrl(id)` và `VideoItem.withMappedDefaults()` làm nguồn duy nhất cho thumbnail dự phòng; `VideoEntity.toVideoItem()` dùng cùng helper. `VideoJson` là codec JSON trung tâm: mọi `VideoItem` được ghi qua `VideoEntity` (khóa chuẩn `videoId`) và đọc lại qua `VideoEntity`, vẫn chấp nhận khóa `id` cũ để không mất hàng đợi/now-playing đã lưu.
- [x] 1.5 Refactor session bình luận theo phạm vi `videoId`: `YouTubeCommentsDataSource` dùng session map theo video (LRU nhỏ), chỉ refresh session của video liên quan, tránh clobber continuation/reply token toàn cục.
- [x] 1.6 Cải thiện cache/metadata: thêm `ExpiringLruCache` dùng chung (TTL + LRU + lock nội bộ); `YouTubeMetadataDataSource` dùng cache này và coalesce request in-flight cùng `videoId`; feed của `YouTubeDataRepository` dùng cùng cache và coalesce request đồng thời theo danh mục bằng `Mutex` + double-check, nên tab/luồng trùng nhau chỉ đi mạng một lần.
- [x] 1.7 Đồng bộ hoá `QueueStore`, `SearchHistoryStore`, `SettingsStore` bằng lock để tránh race read-modify-write.
- [x] 1.8 Giảm trùng lặp parser renderer InnerTube: trích xuất `InnerTubeVideoMapping` dùng chung cho channelId/byline, thumbnail/avatar, thời lượng và toàn bộ mapping `videoRenderer`/`gridVideoRenderer`/`playlistVideoRenderer`, `playlistPanelVideoRenderer`, `lockupViewModel`; `YouTubeWebDataSource` và `YouTubeMetadataDataSource` đều delegate về mapper này (không còn bản sao parser trong từng nguồn).

## 2. Player layer
- [x] 2.1 Thống nhất API repeat/auto-play: `PlaybackCoordinator.cycleRepeatMode()` suy ra chế độ hiện tại và chuyển qua `setAutoPlayMode(next)` để đồng bộ `RepeatMode`, `autoNext` và `pauseAtEndOfMediaItems` theo một mô hình nhất quán.
- [x] 2.2 Làm rõ state machine trong `PlaybackCoordinator`/vòng đời phiên phát: thêm `SessionPhase` (`IDLE/RESOLVING/READY/FAILED/CLOSED`) với bảng chuyển trạng thái tường minh trong `PlaybackSessionMachine` (`canTransitionTo` + `transitionTo` trả `false` thay vì ném lỗi); coordinator dùng machine này cho mọi lần đổi pha, expose `sessionPhase: StateFlow<SessionPhase>` và bỏ enum/field rải rác. Có unit test cho luồng hợp lệ, retry và chuyển đổi không hợp lệ.
- [x] 2.3 Thống nhất ngữ nghĩa queue navigation: thêm contract `PlaybackNavigation` (`NativeNext/NativePrevious/SeekToStart/LoadMoreMix/None/Play`) với `PlaybackQueue.nextNavigation()`/`previousNavigation()`; coordinator chỉ thi hành quyết định của hàng đợi cho cả next/previous (native playlist, tua về đầu khi quá 3 giây, playStack/mix, tải thêm mix). `onAdvancedTo` giữ `playStack` khi auto/native chuyển ngoài mix; `hasPrevious/hasNext` phản ánh target khả dụng + `mix.hasMore`. Có unit test cho mọi nhánh navigation.
- [x] 2.4 Gom/debounce áp dụng quality cho nguồn progressive: `applyNetworkQuality` áp track constraints ngay cho adaptive nhưng debounce việc `applyProgressiveQuality` (rebuild media items) để tránh thrash khi mạng/cài đặt đổi nhanh.
- [x] 2.5 Siết chặt SponsorBlock: cancel/reset state khi load/reset/settings đổi, re-validate điều kiện (enabled/whitelist/video hiện tại) trước khi apply segments async, dọn manual/unskip/grace state khi cần, và chỉ skip/check khi ngữ cảnh còn hợp lệ.
- [x] 2.6 Dọn/siết chặt nhánh yếu: xoá API không dùng `PlaybackQueue.consumePrevious()`; `PlaybackQueueManager` evict `resolvedById` khi trim cửa sổ native. *Giữ lại có chủ đích (tương thích/public API nội bộ):* `PlaybackQueue.consume()` (đang dùng), chuỗi `cycleRepeatMode` (đã thống nhất hành vi), `PlaybackEngine.release()` và lifecycle network monitor (phục vụ vòng đời cấp process/khả năng tái sử dụng, chưa gỡ để tránh ảnh hưởng runtime).

## 3. UI layer
- [x] 3.1 Helper/chung hoá "phát video + mở Player" và policy/action assembly: `PageActivity.playAndOpenPlayer(...)`/`openPlayer(...)` dùng chung cho Home/Subscriptions/Library/Search và cả mini player; `videoCardActions(...)` là builder duy nhất cho thẻ video ở Home/Library/Subscriptions/Search/Player, truyền thẳng callback nullable, map `onRemove` theo `videoId` và giữ mặc định chia sẻ ở một chỗ.
- [x] 3.2 Chuẩn hoá UI state/render (giảm combine lồng/side-effect/fan-out): thêm `HomeUiState` và một entry `HomeNativeView.render(state)`; `HomeViewModel` tổng hợp feed/cá nhân hoá/thư viện thành một `StateFlow` duy nhất, bỏ 6 hàm `set...` và các `combine` lồng trong Activity nên thứ tự render không còn phụ thuộc collector.
- [x] 3.3 Tái dùng component/util và thống nhất adapter update strategy (DiffUtil/guard): `HomeAdapter` dùng `DiffUtil` (`HomeRowDiff`) cho thay đổi row và `notifyItemRangeChanged` khi chỉ đổi state hiển thị; Library/Subscriptions/Search/Settings đã dùng `DiffUtil`/so sánh nội dung từ trước; chip danh mục/tab cập nhật mục tiêu thay vì `notifyDataSetChanged`.
- [x] 3.4 Thống nhất kênh message/error/retry và bề mặt hành động: gom nhãn "Thử lại" về `action_retry`; thêm `ErrorPresentation`/`AppError.presentation(context)` và dùng cho overlay/empty state Trang chủ, Tìm kiếm (cùng nhãn nút, tiêu đề, hướng dẫn), đồng thời cập nhật layout Home offline, Search error và Player HUD.
- [x] 3.5 Dọn API UI không dùng/ít giá trị: đã xoá `LibraryNativeView.clearHistoryDialogNeeded()`; thay mapping Settings thủ công bằng `PurePlayerState.toSettingsState()`; bổ sung lưu/khôi phục state khi tiến trình bị thu hồi cho tab/danh mục Trang chủ và từ khoá Tìm kiếm (Library đã có sẵn), tránh tải/đặt lại trùng khi chỉ xoay màn hình.
- [x] 3.6 Cải thiện `HomeViewModel` flow (giảm request/version flags thủ công): feed dùng `MutableSharedFlow<FeedRequest>` + `flatMapLatest` (request cũ tự huỷ), cá nhân hoá dùng `combine(history, refreshToken)` + `distinctUntilChanged` theo seed + `flatMapLatest`, bỏ `feedRequestId`/`homeMixesRequestId`/`Job` thủ công; tách `buildHomeSuggestions` (round-robin, thuần) và thêm unit test.
